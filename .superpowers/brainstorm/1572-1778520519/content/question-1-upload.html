Upload & Storage Approach

How should we handle video upload during development vs production?

The codebase has S3 infrastructure in place, but we need to decide how the upload flow works. Choose your preferred approach:

A

S3 Only (Production-Ready)

How it works: Upload video directly to S3 using presigned URLs, then trigger AI analysis

Pros

  • Production-ready from day one
  • Scales properly
  • No dual code paths

Cons

  • Requires AWS credentials to develop
  • Incurs S3 costs during testing
B

Dual Mode (Development Flexibility)

How it works: Use localStorage/IndexedDB in dev (blob URLs), S3 in production (env flag toggle)

Pros

  • No AWS credentials needed for local dev
  • Faster iteration
  • No cloud costs during development

Cons

  • Two code paths to maintain
  • Local storage limits (typically ~50MB)
  • Can't test S3 integration locally
C

LocalStack for Development

How it works: Use LocalStack (local S3 emulator) in dev, real S3 in production

Pros

  • Tests real S3 behavior locally
  • Single code path
  • No cloud costs in dev

Cons

  • Extra Docker service to manage
  • LocalStack setup complexity
  • Not always perfect S3 parity

Note: I noticed the dashboard currently uses localStorage for presentations (see getPresentationsFromStorage()). This suggests Option B might already be partially in place.
